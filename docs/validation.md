# 兼容性与安装检查

## 运行条件

服务以 Linux 容器运行，可使用具备相应 Docker 运行能力的服务器、个人电脑或 NAS。部署位置不限定为 NAS；镜像架构、挂载路径、文件权限和音箱网络连接需要与实际主机匹配。

使用项目安装脚本还需要 Python 3.8+ 和 Docker 操作权限。音箱必须能够访问主机发布的 Songloft 地址，主机需要能够访问镜像仓库、上游网页及音频 CDN。

## 兼容性参考

| 项目 | 参考环境 |
| --- | --- |
| 主机 | 群晖 NAS，Linux amd64 / x86_64 |
| 音箱 | 小爱音箱 Pro（LX06） |
| Docker | Engine 24.0.2 |

组件版本、镜像引用及配套文件校验值见 [versions.json](../versions.json)。其他主机或音箱型号应先核对兼容性，再按下方清单检查实际播放效果。

## 脚本与架构限制

- 默认镜像配置固定为 `linux/amd64`，没有自动选择其他架构镜像的逻辑。
- 安装脚本使用 Linux 本机路径、Unix 文件权限和本地 Docker socket，当前会拒绝其他执行环境。
- ARM、Windows、macOS、Docker Desktop 或远程 Docker 场景不在当前安装脚本的适用范围内，需要先调整镜像引用、脚本、目录映射、权限和网络配置。
- 示例路径仅用于说明，必须替换为目标主机上的实际目录。

## 安装后检查

完成 [README](../README.md) 中的配置后，按下列项目检查：

| 检查项 | 预期结果 |
| --- | --- |
| 容器与健康状态 | 两容器运行稳定，UZZ 返回 `ready` |
| 宿主版本 | Songloft 自报版本与 `versions.json` 一致 |
| 目录权限 | 原曲库只读，`uzz-online` 可写，数据目录允许执行程序 |
| 音箱连接 | MIoT 登录成功，目标设备已启用管理，音箱可访问主机地址 |
| 本地点播 | 原有本地歌曲正常发声 |
| 在线兜底 | 本地未命中的歌曲可搜索并播放 |
| 自动保存 | 完整缓存后生成本地文件，歌曲类型转为 `local` |
| 重复点播 | 播放本地文件，不新增在线搜索和取链调用 |
| 断源播放 | 停止 UZZ 后，已保存歌曲和原有本地歌曲仍可播放 |
| 重启恢复 | 配置保留，服务恢复后可继续点播和保存新歌 |

具体操作见 [播放与自动保存检查](../README.md#检查播放与自动保存)。检查未通过时，按 [运维与排障](operations.md) 中的顺序定位。

在线搜索和首次播放依赖上游服务及网络。完整保存并转为本地歌曲后，后续播放依赖本地文件，不再依赖原临时音频 URL。
